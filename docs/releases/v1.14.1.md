# challenge-kit v1.14.1

This release updates `github.com/redis/go-redis/v9` from `v9.23.0` to
`v9.24.0`. The Go requirement remains `1.27.4`. There are no changes to the
challenge API, stored records, hash formats, or activation scripts.

## Redis client behaviour

Applications provide their Redis client to challenge-kit. The
[go-redis v9.24.0 notes](https://github.com/redis/go-redis/releases/tag/v9.24.0)
describe changes that can affect those clients:

- Command retries no longer restart an exhausted built-in dial sequence for
  the same endpoint. Connection failures can therefore return sooner.
- With `ContextTimeoutEnabled`, socket timeouts caused by the caller's
  deadline match `context.DeadlineExceeded` through `errors.Is`; the original
  transport error remains in the chain. Avoid classifying errors by text.
- `MaxActiveConns` counts dedicated connections and in-flight dial reservations
  as well as pooled connections. Clients that exceeded the configured limit
  can now receive pool-exhaustion errors.

The existing fail-closed contract still applies: a backend error is not a
successful verification, and a lost response does not prove that a Redis
mutation was rolled back. Keep the application's retry and timeout policy
consistent with that contract.

## Upgrade and rollback

```sh
go get github.com/soulteary/challenge-kit@v1.14.1
```

No challenge data migration is required when upgrading from `v1.14.0`.

To select the previous challenge-kit release:

```sh
go get github.com/soulteary/challenge-kit@v1.14.0
```

Go's minimal version selection may retain `go-redis v9.24.0` after that
command. If the Redis client itself must be rolled back, inspect the
application's module graph and review its other dependency requirements
before explicitly selecting `go-redis v9.23.0`.
